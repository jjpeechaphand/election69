# กระบวนการข้อมูล (Data Pipeline) — ตามลำดับ vis-3 p.34–36

```
Data acquisition ─► Editable data ─────────────► Loading ───────────► Transformation/aggregation ─► Visual mapping ─► Rendering ─► Validation
 (กกต. snapshot)    (dist/data/<ปี>/*.csv,        (e69-source.js:       (e69-data.js, 1 แหล่งคำนวณ)  (e69-app/analysis)  (D3 SVG/HTML)  (validate(), tests)
                     แก้ด้วย Excel ได้)             CSV หรือ bundle.js)
```

ตั้งแต่ 4 พ.ย. 2569 หน้าเว็บอ่านข้อมูลจาก **ไฟล์ CSV ที่แก้ไขได้** ใน `dist/data/` (หนึ่งโฟลเดอร์ต่อการเลือกตั้ง `elections.csv` เลือกครั้งที่แสดง) วิธีแก้และอัปเดตอยู่ใน `DATA_EDITING_GUIDE.md` ขั้นตอนเดิมข้างล่าง (prepare_data.py → data.js) คือที่มาของข้อมูลปี 2569 ซึ่งถูกส่งออกเป็น CSV ครั้งเดียวด้วย `scripts/export_election_csv.py`

## 0. Editable data → loading (รอบข้อมูลแก้ไขได้)
- **ไฟล์ต่อหัวข้อ**: election.csv (ค่าทั่วไปแบบ key/value) parties.csv provinces.csv constituencies.csv candidates.csv party_list_votes.csv (แบบกว้าง: หนึ่งคอลัมน์ต่อพรรค) sources.csv เป็น UTF-8 พร้อม BOM ให้ Excel แสดงภาษาไทยได้ หัวคอลัมน์ = คำไทย + (คีย์อังกฤษ)
- **การอ่าน** (`dist/js/e69-source.js`): บนเว็บเซิร์ฟเวอร์ fetch ไฟล์ CSV โดยตรง (ปุ่มอัปเดตใช้ `cache: 'no-store'` + query `?t=` เพื่อข้ามแคชทุกชั้น) ถ้าเปิดจาก file:// ซึ่งเบราว์เซอร์ห้าม fetch จะโหลด `dist/data/bundle.js` (ข้อความ CSV เดียวกันที่ฝังไว้) ทั้งสองทางใช้ตัวแปลงชุดเดียวกัน
- **การแปลง**: CSV → โครงสร้างเดิมที่ e69-data.js ใช้ (เขต ผู้สมัคร พรรค สรุป ทะเบียนจังหวัด ภาพบุคคล ตำแหน่งหกเหลี่ยม ความหนาแน่น) ค่าว่าง = null (ไม่แทน 0) ที่นั่ง สส.เขต ที่เว้นว่างนับจากผู้ชนะ รหัสผู้สมัครสร้างจากอักษรย่ออังกฤษของจังหวัด_เขต_หมายเลข
- **การตรวจ**: ข้อมูลผิดรูปแบบหยุดด้วยข้อความภาษาไทยระบุไฟล์ แถว คอลัมน์ (เช่น พรรคไม่มีใน parties.csv คะแนนไม่ใช่ตัวเลข รหัสเขตผิด) `scripts/build_data_bundle.py` ตรวจแบบเดียวกันก่อนเผยแพร่และเพิ่มคำเตือนเชิงความสอดคล้อง (คะแนนรวม ≠ บัตรดี, จำนวนเขตไม่ตรง, ไม่พบไฟล์รูป) แล้วสร้าง bundle.js

## 2. Data preparation
- `scripts/prepare_data.py` (เดิม) → `dist/data.js` / `data.json`: 400 เขต, 60 พรรค, คะแนนผู้สมัคร, คะแนนบัญชีรายชื่อต่อเขต, ผู้มีสิทธิ, ผู้มาใช้สิทธิ, บัตรเสีย/ไม่เลือกผู้ใด แยกชนิดบัตร
- `scripts/prepare_two_page.py` (ใหม่) อ่าน ZIP และไฟล์ JSON แบบอ่านอย่างเดียว ตรวจว่า 77 รหัสจังหวัดตรงทะเบียน กกต. ตำแหน่งไม่ซ้ำ ชื่ออังกฤษครบ แล้วเขียน `dist/reference-data.js` (`window.E69_REFERENCE`) และ `dist/district-shapes.js` (พิกัดปัด 4 ตำแหน่ง ยืนยันว่ามีครบ 400 รหัสเขตของ กกต.) ชื่อย่อสองชื่อในตาราง ZIP (กรุงเทพฯ, อยุธยา) ถูกจับคู่กับรหัส 10/14 อย่างชัดเจน แต่หน้าเว็บใช้ชื่อเต็มจากทะเบียน กกต. เสมอ; ถ้ามี `verification/ect-recheck-*.json` จะใส่สรุปผลตรวจล่าสุด (`liveCheck`) ลงใน reference-data.js เพื่อแสดงในกล่องที่มาข้อมูล
- `scripts/prepare_mp_portraits.py --raw <โฟลเดอร์เดียวกัน>` ทำภาพผู้สมัครให้อยู่ในรูปแบบเดียวกับภาพหัวหน้าพรรค ทีละขั้น:
  1. ตัดขอบกระดาษขาวของภาพที่สแกนจากภาพพิมพ์ (ตัดเฉพาะเมื่อแถบที่เกือบขาวทั้งแถวที่ขอบเปลี่ยนเป็นสิ่งที่ไม่ขาวทันที ขอบที่มีตัวอักษรของร้านถ่ายรูปหรือลายเซ็นก็ตัดได้ ฉากขาวที่ต่อเนื่องไม่ถูกตัด) และแถบคำบรรยายที่ขอบล่าง (เส้นแนวนอนคมตลอดความกว้างภาพในช่วง 12% ล่าง); ภาพโปสเตอร์ 1 ภาพตัดส่วนตราพรรคเหนือศีรษะด้วยกรอบที่กำหนดเอง (`PHOTO_CROPS`)
  2. ตัดพื้นหลังด้วย u2net (rembg โมเดลเดียวกับภาพหัวหน้าพรรค) และเลือกส่วนของหน้ากากที่มีใบหน้า (ตัดตราพรรค/โลโก้ที่โมเดลเลือกมาด้วย) ไม่นับร่องรอยจาง ๆ ที่โมเดลทิ้งไว้ตามขอบภาพเป็นตัวคน
  3. หาใบหน้าด้วยตัวตรวจจับ LBP ของ scikit-image ที่ 3 ขนาด เลือกเฉพาะกรอบระดับศีรษะ ใช้ค่ามัธยฐาน; ถ้ามีน้อยกว่า 2 กรอบ รันอีกรอบด้วยเกณฑ์ผ่อนลง และถ้ากรอบน้อยมากให้ตรวจความกว้างกับความกว้างศีรษะ; 3 ภาพที่ตัวตรวจจับผิด (ผ้าคลุมศีรษะ หน้าเข้มบนฉากดำ โปสเตอร์) ใช้กรอบที่ตรวจด้วยตา (`FACE_OVERRIDES`) แบบเดียวกับจุดอ้างอิงที่วางด้วยมือของภาพหัวหน้าพรรค
  4. **ส่วนตัวที่ u2net ทิ้ง** (พบบ่อยกับสูทสีเข้มบนฉากฟ้า ซึ่งโมเดลเก็บแค่หน้า เสื้อเชิ้ตและเนกไท): ทำเฉพาะเมื่อหน้ากากของโมเดลขาดช่วงอกหรือลำตัวล่างจริง ประมาณสีฉากจากขอบบนและขอบข้างเหนือไหล่ (พหุนามอันดับสองต่อช่องสี Lab) แล้วให้ random walker ของ scikit-image ตัดสินตามขอบภาพจริง (เมล็ดฉาก = ขอบภาพเหนือไหล่; เมล็ดคน = ส่วนที่โมเดลแน่ใจ อกใต้คาง และขอบล่างที่ต่างจากฉากมาก) ฉากที่ไล่เฉดไม่มีขอบจึงเป็นฉาก ส่วนเสื้อผ้ามีขอบจึงเป็นคน; รับเฉพาะส่วนที่อยู่ใต้แนวไหล่และต่อกับตัวคน ส่วนที่แตะขอบบน คลุมขอบข้างเหนือไหล่ หรือสีไม่ต่างจากฉากชัดเจน ถือว่าผิดและไม่ใช้
  5. ฉากที่โมเดลเก็บติดมาเหนือคาง ห่างจากใบหน้า และสีเหมือนฉาก ถูกนำออก
  6. เสื้อผ้าที่โมเดลทำให้โปร่งแสงภายในร่างถูกทำให้ทึบ (เติมรูภายในร่าง คงขอบนุ่มของโมเดล)
  7. ตาข่ายนิรภัย: ถ้าการซ่อมทำให้ฉากข้างศีรษะที่โมเดลปล่อยใสกลายเป็นทึบ (กรอบภาพหรือแถบล่างปิดวงรอบฉาก) หรือทับมุมบนของภาพ ให้กลับไปใช้หน้ากากของโมเดลเอง
  8. ถ้าอกยังหายเกือบทั้งหมด (เสื้อขาวบนฉากขาวไม่มีขอบให้หา หรือดำบนดำ) ใช้พิกเซลจริงของภาพจางเป็นวงรีใต้ศีรษะแทนการเหลือแต่หัวลอย
  9. ย่อ/ขยายและวางให้กรอบใบหน้าตรงกับกรอบใบหน้าของภาพหัวหน้าพรรค 10 ภาพที่วัดด้วยตัวตรวจจับเดียวกัน (กลาง 258, 226.5 กว้าง 186 px ในภาพ 512) ปรับแสง ±10% และสมดุลสี ±5% แบบภาพหัวหน้าพรรค ขอบตัวที่ถูกขอบภาพต้นฉบับตัดจางลง 16 px
  10. บันทึก WebP โปร่งใส 256×256 ที่ `dist/assets/candidates/2569/<รหัส>.webp`

  การตรวจด้วยตา: ทุกภาพบนพื้นลายตาหมากรุกสีจัด (ส่วนโปร่งใสที่ผิดจะเห็นทันที ต่างจากพื้นสีเรียบที่ซ่อนสูทสีเข้มที่หายไปได้) และวัดอัตโนมัติ เช่น ความทึบช่วงอก ความทึบข้างศีรษะ ความกว้างศีรษะเทียบกรอบใบหน้า

  รายงานการวัดและธงทุกภาพอยู่ที่ `research/mp_portraits_processing.json` และแผ่นรวมภาพ `research/mp_portraits_qa/` ไม่มีการสร้างหรือแต่งใบหน้าหรือเสื้อผ้า ทุกพิกเซลมาจากภาพต้นฉบับ
- การทำความสะอาด: ไม่แก้ตัวเลขต้นทางเลย ชื่อพื้นที่ (`zone`) ถูกแยกเป็นชื่อหลัก (อำเภอ/เขต) กับวงเล็บ "เฉพาะ…/ยกเว้น…" ตอนสร้างดัชนีค้นหา; ตำบลหลัง "เฉพาะ" ค้นได้ ส่วนหลัง "ยกเว้น" ไม่ถูกจัดเป็นของเขตนั้น

## 3. Transformation & aggregation — `dist/js/e69-data.js`
แหล่งคำนวณเดียวที่ทุกมุมมองใช้ร่วมกัน (tooltip, แผงจังหวัด, sheet มือถือ, KPI, กราฟทุกกราฟ, ค้นหา)
- ต่อเขต (`ElectionModel.calculate` เดิม): เรียงคะแนน ผู้ชนะ อันดับสอง ส่วนต่าง = ผู้ชนะ − อันดับสอง, ร้อยละส่วนต่าง = ส่วนต่าง ÷ บัตรดีแบบแบ่งเขต × 100, เสมอ → ไม่กำหนดผู้ชนะ
- อัตราการใช้สิทธิ = Σผู้มาใช้สิทธิ ÷ Σผู้มีสิทธิ × 100 คำนวณจากเขตที่มีทั้งสองค่าเท่านั้น และรายงานความครบถ้วน (n/N) ไม่เฉลี่ยร้อยละรายเขต
- ผลรวม (`total`) ไม่แทนค่าที่ขาดด้วยศูนย์ คืน `{value, n, of, complete}` เพื่อแสดง "ข้อมูลไม่ครบ n/N เขต"
- ตารางที่นั่งจังหวัด: นับเฉพาะผู้ชนะรายเขต เรียงจำนวนมาก→น้อย แล้วชื่อพรรค (`localeCompare('th')`) แยกนับเขตที่ยังไม่มีผู้ชนะ
- สัดส่วนคะแนนรวม (จังหวัด/ภูมิภาค) = Σคะแนนพรรค ÷ Σบัตรดีของชนิดบัตรเดียวกัน
- เปรียบเทียบสองบัตรต่อเขต (`ElectionModel.partyComparison` เดิม) ใช้บัตรดีแบบแบ่งเขตและบัตรดีบัญชีรายชื่อเป็นตัวหารแยกกัน ไม่มีผู้สมัคร → ไม่มีค่า (ไม่ใช่ 0); ระดับพรรครวมแบบจับคู่เฉพาะเขตที่ส่งผู้สมัคร (`pairedBallots`) และ cache ต่อพรรค
- ความหนาแน่นจังหวัดผูกกับทุกเขตในจังหวัด (ค่าเดียวกัน) และใช้ในกราฟระดับจังหวัดเท่านั้น
- ความลงตัวของบัตรต่อเขต: `ballotGap` = บัตรดี + บัตรเสีย + ไม่เลือกใคร − ผู้มาใช้สิทธิ (แบ่งเขต) และ `listBallotGap` (บัญชีรายชื่อ) เป็น `null` ถ้าค่าใดขาด ใช้ติดหมายเหตุในแผงเขต ไม่ใช้ปรับตัวเลข
- ทุกค่าถูกคำนวณครั้งเดียวตอนโหลด การชี้เมาส์อ่านจากสรุปที่คำนวณไว้แล้ว ไม่คำนวณ 400 เขตใหม่

## 4. Visual mapping & rendering
- `dist/js/e69-app.js`: หน้าภาพรวม แผนที่ SVG (หกเหลี่ยม pointy-top, จุดศูนย์กลาง x = (col − 0.5·[row คู่])·r·√3, y = row·1.5·r ตามต้นฉบับ) ป้ายชื่อเต็มคำนวณความพอดีด้วย canvas `measureText`
- `dist/js/e69-analysis.js`: กราฟ D3 v7 วาดตามขนาดกล่องจริง และวาดใหม่ด้วย ResizeObserver เมื่อสลับหน้า/ปรับขนาด

## 5. Validation (ภายในระบบและชุดทดสอบ)
- `validate()` ใน e69-data.js รัน 15 การตรวจตอนโหลด แสดงผลในหน้าต่าง "ที่มาข้อมูลและวิธีอ่าน" (เช่น ที่นั่งรวม = 500, ผลรวมผู้มาใช้สิทธิ = สรุป กกต., ไม่มีค่าขาด, ผู้มาใช้สิทธิไม่เกินผู้มีสิทธิ, ผัง 77 ช่องไม่ซ้ำ และหมายเหตุความไม่ลงตัวของบัตร 17/12 เขต)
- `scripts/recheck_ect.py` เทียบกับเว็บ กกต. สด (ข้อ 1) ผลแสดงในหน้าต่างเดียวกันหัวข้อ "ตรวจเทียบกับเว็บไซต์ กกต."
- `tests/two-page-data.test.cjs` คำนวณซ้ำจากข้อมูลดิบแบบอิสระ, `tests/two-page.e2e.cjs` ตรวจบนเบราว์เซอร์จริง ดู `VALIDATION_REPORT.md`

python -I -X utf8 output/election69/scripts/build_data_bundle.py   # ตรวจไฟล์ CSV ที่แก้แล้ว และสร้าง dist/data/bundle.js

node --test tests/two-page-data.test.cjs
node tests/two-page.e2e.cjs
python scripts/package_two_page.py
